# Storybook engine

Shared source for every bilingual/multilingual picture-book series (`../taiwan-ehon/`,
`../japan-ehon/`, and future siblings). See `../taiwan-ehon/README.md`'s "The shared engine"
section for the history and the zero-visible-change guarantee this refactor was built under.

## Why series folders hold real copies, not references

GitHub Pages serves plain static files with no build/include step, and a service worker only
ever reliably caches requests made by pages it controls at its own scope. To keep each series
independently installable (its own manifest, its own offline PWA, its own Cache Storage
namespace) without depending on any shared runtime URL outside that series' own folder, every
series folder keeps a real, byte-identical copy of this engine's runtime files:
`ehon.js`, `app.js`, `offline.js`, `sw.js`, `generate-book-pages.js`, `test-dom.js`,
`continuous.js`, `generate-audio-timing.js`, and a combined `ehon.css` (this folder's shared
layout rules plus that series' own `theme.css` color tokens/pattern). The three silence clips
under `engine/silence/` (`language.mp3`, `sentence.mp3`, `page.mp3` — see "Screen-off listening"
below) are copied the same way, byte-for-byte rather than as text.

`engine/` is the single source of truth for those copies. After editing anything here, run:

```sh
node engine/build.js          # copies engine/* into every folder in engine/registry.js
```

CI runs `node engine/build.js --check` and fails if a series folder's copy has drifted (i.e. it
was hand-edited instead of edited here and re-synced).

## What stays per-series (never copied)

- `series.config.js` — that series' identity: its own folder name, PWA `basePath`, GA
  `series_id`, shelf/reader copy strings, and which languages/features it turns on. This is the
  only file the copied engine files read to behave differently per series.
- `stories.js` — that series' own story data (hand-authored for taiwan-ehon; generated by
  `engine/build-stories.js` from `stories/*.js` for a series like japan-ehon that keeps one file
  per story — see `japan-ehon/stories/README.md`).
- `theme.css` — that series' own color tokens and decorative pattern.
- `audio-timing.js` — that series' own per-clip narration durations, generated by
  `generate-audio-timing.js` (via ffprobe) from that series' own `audio/*.mp3` clips and the
  shared `silence/*.mp3` files. Regenerate it after adding or re-recording any clip.
- `index.html` — thin and mostly identical across series, but hand-authored per series (not
  generated), so each series can add its own head metadata, cross-link, and "coming soon" state
  without touching another series' markup.
- `images/`, `audio/`, `icons/`, `manifest.webmanifest`, and the generated `<book-id>/` folders.

## Screen-off listening

`continuous.js` builds the whole book's clips for the reader's chosen listening mode — plus
silence clips (`silence/*.mp3`) standing in for the gaps between them — into one in-memory MP3
Blob, so a single already-playing `<audio>` element (rather than `app.js`'s clip-by-clip
`createNarrator`) is what has to keep going with the screen off. `generate-audio-timing.js`
precomputes every clip's exact duration (via ffprobe) at build time into that series' own
`audio-timing.js`, so `continuous.js` can work out which page and line is currently sounding from
`audio.currentTime` alone, with no re-measurement at runtime. See taiwan-ehon/README.md's
"Listening with the screen off" section for the reader-facing behavior and what has and hasn't
been verified on a real device.

## Tests

`*.test.js` here run against the taiwan-ehon dataset (the only series with full real content) for
everything content- and behavior-specific — narration, routing, analytics payloads, PWA asset
lists. `multi-series.test.js` and `url-existence.test.js` instead loop over every folder in
`registry.js` (or, for the latter, hand-list taiwan-ehon's own historical URLs) to catch drift,
config mistakes, and — the one hard requirement this whole refactor exists to protect — any
taiwan-ehon URL quietly disappearing.

```sh
node --test engine/*.test.js
```

## Adding a new series

1. Add its folder name to `registry.js`.
2. Create `<folder>/series.config.js` (copy an existing one and change the identity fields),
   `<folder>/theme.css`, `<folder>/index.html`, `<folder>/manifest.webmanifest`, and
   `<folder>/icons/`.
3. Either hand-write `<folder>/stories.js` (taiwan-ehon's approach) or create
   `<folder>/stories/` and run `node engine/build-stories.js`.
4. `node engine/build.js` to populate the runtime file copies, then
   `node <folder>/generate-book-pages.js` once there is at least one story.
5. Add `<folder>` to `pages.json` (see `.github/scripts/validate_pages.py`).
